---
title: SHAKE256
description: The FIPS 202 sponge at 256-bit security. Squeezes 64 bytes by default, and exactly the 114 Ed448 asks for
---

::algorithm-facts{name="shake256"}
::

SHAKE256 doesn't stop at a fixed digest size. Ask for 114 bytes and it gives you 114. Why 114? Ed448 hashes its keys and signatures with exactly that much. ML-KEM and ML-DSA use it too. SHAKE256 is a FIPS 202 extendable output function. It shares the Keccak sponge with SHA-3 but uses different padding.

Set `outputLength` to a whole number of bytes from zero. The default is 64 bytes, SHAKE256's full 256-bit security. Comparing with `openssl dgst`? Pass `-xoflen 64`, it refuses to pick one for you. Shorter outputs have less collision resistance. Stick with the default unless your protocol specifies another length.

```ts
create("shake256").hash("abc").digest;
// "483366601360a8771c6863080cc4114d8db44530f8f1e1ee4f94ea37e78b5739d5a15bef186a5386c75744c0527e1faa9f8726e462a12a4feb06bd8801e751e4"
create("shake256").hash("abc", { outputLength: 114 }).options;
// { encoding: "hex", outputLength: 114 }
```

```bash
hashes shake256 abc --output-length 114
```

The default digest is the first 64 bytes of that longer output, byte for byte. Nothing gets reshuffled when you ask for more, the sponge just keeps going. Different lengths for one input aren't independent. A result reports `outputLength` in its options only when explicitly set.

Agent tools allow at most 1024 output bytes per call. They also limit rounds times `outputLength` to 64 million bytes. Library callers can choose any length. A gigabyte of SHAKE? Your call.

There's no HMAC mode, and SHAKE doesn't miss it. For direct byte functions, import `shake256(bytes, length)` from `@agntn/hashes/keccak`. The [Hashing](/guide/hashing) guide has more. Compare [SHAKE128](/algorithms/shake128) and [SHA3-256](/algorithms/sha3-256).

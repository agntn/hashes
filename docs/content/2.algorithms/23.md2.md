---
title: MD2
description: Rivest's 1989 hash for 8-bit machines. Broken and Historic since 2011. Here for old signatures and it has HMAC
---

::algorithm-facts{name="md2"}
::

Before [MD4](/algorithms/md4) there was this. Rivest built MD2 in 1989 for 8-bit machines, so it works one byte at a time. Every 16-byte block takes eighteen passes over a 48-byte state. A checksum of all the blocks rides along and gets hashed last.

Where does its table of 256 bytes come from? The digits of π. RFC 1319 just prints the result. This package draws it from π itself, the first time you ask. The shuffle eats 722 digits and lands exactly on the RFC's table. Nothing up the sleeve, and you don't have to take anyone's word for it.

```ts
create("md2").hash("abc").digest; // "da853b0d3f88d99b30283a69e6ded6bb"
create("md2").hash("").digest; // "8350e5a3e24c153df2275c9f80692773"
```

Safe? No. A preimage costs 2^73 instead of 2^128. RFC 6149 moved MD2 to Historic in 2011. It's slow as well, about twenty times slower than MD4 here. Byte by byte has a price.

So why keep it? PKCS #1 still lists `md2WithRSAEncryption`, and old certificates carry it. OpenSSL has left MD2 out by default since 1.0.0, so Node won't compute it at all. HMAC works over its 16-byte blocks, though RFC 6149 warns it can leak bits of the key. Check old data with it. Build nothing new.

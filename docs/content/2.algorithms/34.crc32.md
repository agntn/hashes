::algorithm-facts{name="crc32"}
::

The IEEE CRC-32, the one in ZIP, PNG, gzip and Ethernet. It catches accidental bit flips and nothing else. Anyone can forge a CRC-32 in microseconds, since it's linear.

```ts
create("crc32").hash("123456789").digest; // "cbf43926", the standard check value
create("crc32").hash("The quick brown fox jumps over the lazy dog").digest; // "414fa339"
create("crc32").hash("123456789", { variant: "bzip2" }).digest; // "fc891918"
create("crc32").hash("123456789", { variant: "iscsi" }).digest; // "e3069283"
```

The avalanche panel on the landing makes the linearity visible. Flip one input bit and the CRC changes by a pattern that depends only on where that bit sat, not on the rest of the input. A real hash moves a random half. Printed big-endian, as `crc32` tools write it.

## Byte functions

Import `crc32IsoHdlc`, `crc32Bzip2` or `crc32Iscsi` from `@agntn/hashes/crc` or the root to avoid bundling the unused variants. Each takes a `Uint8Array` and returns four big-endian bytes. Use `crc32(data, variant)` for runtime selection.

```ts
import { crc32IsoHdlc, crc32Bzip2, crc32Iscsi } from "@agntn/hashes/crc";

const bytes = new TextEncoder().encode("123456789");
crc32IsoHdlc(bytes).toHex();
crc32Bzip2(bytes).toHex();
crc32Iscsi(bytes).toHex();
```

## Variants

`variant` picks which CRC-32. The names come from the CRC catalogue.

| `variant` | Who uses it |
|---|---|
| `iso-hdlc` (default) | zlib, gzip, ZIP, PNG, Ethernet |
| `bzip2` | bzip2, after every block and once more for the stream |
| `iscsi` | CRC-32C: iSCSI, SCTP, ext4 and Btrfs metadata, Google Cloud Storage |

Same polynomial, same all-ones start and finish. bzip2 just reads the bits the other way round, so the answer is different. A checksum from a `.bz2` file that matches neither is usually the stream CRC, which rotates the running value left by one bit before each block's CRC goes in. One block and the two agree.

Need CRC-32C? That's `iscsi`, the catalogue's name for it. Everyone else says CRC-32C or Castagnoli, and `crc32c` as an algorithm name points you here.

It's zlib's CRC-32 with one part swapped. The reflection and the start and finish stay put. Only the polynomial changes, and the answer goes with it. Castagnoli's polynomial catches more errors, which is why storage and networking went with it.

CPUs even ship an instruction for it. This library ignores the hardware and does it with plain JS tables.

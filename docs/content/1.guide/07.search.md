## Which words made this hash?

Puzzles love this trick. Take a few answers, glue them together, hash the lot. The digest is your password. You found the words. Great. In which order, though? Joined with what? Lowercase? Hashed twice?

Nobody wants to write that loop again. `searchDigest` takes the words and the digest and tries everything:

```ts
import { searchDigest } from "@agntn/hashes";

const found = searchDigest(
  Uint8Array.fromHex("250f37726d6862939f723edc4f993fde9d33c6004aab4f2203d9ee489d61ce4c"),
  { words: ["heisenbergsuncertaintyprinciple", "giveitjustonesecond", "jacquefresco"] },
);
found.recipe;
// { words: ["jacquefresco", "giveitjustonesecond", "heisenbergsuncertaintyprinciple"],
//   joiner: "", case: "as-is", algorithm: "sha256", rounds: 1,
//   input: "jacquefrescogiveitjustonesecondheisenbergsuncertaintyprinciple" }
```

That's the OpenSSL password of GSMG phase 3.2. Three words, no spaces, SHA-256 in hex. Done before you could type the second guess.

## What does it try?

Every subset of the words, the smallest first, in every order. Each word at most once. Then:

- **Joiners.** Nothing, a space, a comma, a line feed. Or your own list.
- **Cases.** As given, all lowercase, all uppercase, each word capitalized.
- **Algorithms.** Every fixed-length digest as long as yours. A 32-byte target gets SHA-256, SHA3-256, Keccak-256, BLAKE3 and the rest of its size. A 20-byte one gets SHA-1, SHA-0, RIPEMD-160 and HASH160. A 4-byte one gets CRC-32, its BZIP2 variant and XXH32 too, the same readings [identify](/guide/identify) lists.
- **Rounds.** Up to `rounds` deep. Each round after the first hashes the digest's bytes, its lowercase hex or its uppercase hex.

Two cases that give the same text count once. `alpha` lowercased is still `alpha`, so it's hashed once. A word listed twice is an error, not a quiet double. So are `Moon` and `moon` with lowercase on the list: one of them is enough.

One overlap stays. With no joiner, `ab` alone and `a` plus `b` make the same text, so it's hashed twice. Cheap, and the count includes it up front.

The KDFs stay out. They need a salt, and then it isn't a transform of your words anymore.

## How long will it take?

You know before it starts. `total` is the exact number of hashes the scope holds, counted without listing them. `onProgress` hears it first, then the running count every 100,000 hashes.

Each hash costs a couple of microseconds. Five lowercase words make 3,855 texts, and every algorithm of the digest's length hashes each one. Gone in a blink. Nine words make 11,836,827 texts. That's minutes, not seconds. Order matters, and nine words have a lot of orders.

`limit` stops it early, and `stopped` tells you it did. The first match ends the search either way.

## From the shell

The recipe and the text that was hashed go to stdout. The count and the verdict go to stderr:

```bash
hashes search 250f37726d6862939f723edc4f993fde9d33c6004aab4f2203d9ee489d61ce4c \
  heisenbergsuncertaintyprinciple giveitjustonesecond jacquefresco 2>/dev/null
# sha256 of the words "jacquefresco", "giveitjustonesecond", "heisenbergsuncertaintyprinciple" joined by "", case as-is
# input "jacquefrescogiveitjustonesecondheisenbergsuncertaintyprinciple"
```

`--joiners` takes a JSON array, since a joiner can be a comma: `--joiners '["", "-", "_"]'`. `--cases`, `--algorithms` and `--chains` take comma lists. `--limit` stops at 100,000,000 hashes unless you say otherwise. On a terminal the running count ticks over itself. A pipe gets the total and the verdict, nothing else.

## Nothing matched. Now what?

The answer says exactly what it covered. Here a guess wrote the name as two words and kept to SHA-256:

```bash
hashes search 250f37726d6862939f723edc4f993fde9d33c6004aab4f2203d9ee489d61ce4c \
  "jacque fresco" giveitjustonesecond heisenbergsuncertaintyprinciple --algorithms sha256
# Searching 153 hashes
# NO MATCH in 153 hashes
# Covered 1 to 3 of the words "jacque fresco", "giveitjustonesecond", "heisenbergsuncertaintyprinciple"; joiners "", " ", ",", "\n"; cases as-is, lower, upper, title; algorithms sha256; 1 round.
```

So is the idea dead? No. Only that scope is. The real word had no space, or the digest went through three rounds, or there's a fourth word you haven't found. Widen one thing at a time. The exit code is 1, so a script can tell.

## For agents

`hashes_digest_search` takes the same things as arguments and answers in the same lines. A tool call stops at a million hashes, fewer when the words run long, and then names the arguments to narrow. Every word comes back in quotes, so a word with a line feed in it can't fake a line of the answer. Brute force, but polite about it.
